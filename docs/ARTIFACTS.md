# Proving artifacts and verifying key

NULL does not define its own circuit or cryptography. It uses the Semaphore v4 circuit and its published artifacts.

## Circuit

- Semaphore v4 (`semaphore.circom`), Merkle tree depth **16** (`MAX_DEPTH = 16`), LeanIMT inclusion, Baby Jubjub public key derivation, Poseidon commitments and nullifiers.
- Private inputs: `secret`, `merkleProofLength`, `merkleProofIndex`, `merkleProofSiblings[16]`.
- Public inputs: `message` and `scope` (both already hashed as `keccak256(x) >> 8` by the client library); outputs `merkleRoot`, `nullifier`.
- snarkjs public signal order: `[merkleRoot, nullifier, message, scope]`. The program builds exactly this array.

## Verifying key

`program/programs/null-verifier/src/verifying_key.rs` is generated by `scripts/gen-verifying-key.ts` from
`node_modules/@semaphore-protocol/proof/src/verification-keys.json` (sha256
`d96ec60593b6fc2334f1f04e008e07425d5536d7777f6ac21d996fc80779b3c9`), entries `vk_delta_2[15]` and `IC[15]`, plus the
shared `vk_alpha_1`, `vk_beta_2`, `vk_gamma_2`. This is the same key `verifyProof()` uses off chain, so a proof the
library accepts is a proof the program accepts, and vice versa.

Byte layout for Solana (`groth16-solana`): 32-byte big-endian limbs; G1 as `x | y`; G2 as `x.c1 | x.c0 | y.c1 | y.c0`
(imaginary part first, matching the EVM precompiles and Solana's alt_bn128 syscalls). The proof's A point is negated
(`y -> p - y`) before submission because the verifier evaluates `e(A,B) e(inputs,gamma) e(C,delta) e(alpha,beta) == 1`.

Cross-checks performed:

- `scripts/gen-fixtures.ts` verifies every fixture proof with Semaphore's verifier and with an independent noble-curves pairing computation that parses the Solana byte layout (`scripts/lib/pairing-oracle.ts`), and asserts that flipping one byte breaks it.
- `program/tests` verify the same bytes inside the SVM with the embedded key.
- `tests/unit` assert the TypeScript conversion reproduces the exact bytes the SVM accepted.

## Trusted setup

Semaphore v4 artifacts come from the Semaphore v4 trusted setup ceremony run by PSE (phase 2 on top of the Perpetual
Powers of Tau phase 1). Soundness of every Semaphore v4 deployment, including NULL, assumes at least one honest
participant in that ceremony. NULL adds no ceremony of its own and introduces no new circuits. See
https://github.com/semaphore-protocol/semaphore and https://ceremony.pse.dev for the ceremony records.
